# API التطبيق — التعبئات (v1)

التعبئات اللي يختار منها البائع وقت البيع: قطعة، درزن، باكيت. القائمة **وحدة لكل المواد**. الهيدرات والتوكن مشروحين بـ [login.md](login.md).

---

## عرض التعبئات

```http
GET /api/v1/packages
Authorization: Bearer <التوكن>
Accept-Language: ar
```

يحتاج صلاحية `app.checkout`، وبدونها يرجع `403`.

### الجواب — `200`

```json
{
  "data": [
    { "value": "piece", "label": "قطعة", "size": 1 },
    { "value": "dozen", "label": "درزن", "size": 12 },
    { "value": "packet", "label": "باكيت", "size": 20 }
  ]
}
```

| الحقل | معناه |
|---|---|
| `value` | مفتاح التعبئة. هذا اللي تدزّه ويا البند بالبيع |
| `label` | اسمها بلغة `Accept-Language`. اعرضه للبائع |
| `size` | كم قطعة بالتعبئة الوحدة |

> **لا تكتب القائمة بالتطبيق.** خذها من هذا الرابط دايماً. إذا تغيّرت أو انضافت تعبئة، تغيّرها يوصلك بلا إصدار جديد.

### شلون تستخدمها بشاشة البيع

1. البائع يختار التعبئة ويكتب العدد، مثلاً **درزن × 2**.
2. احسب القطع: `العدد × size` = `2 × 12` = **24**.
3. دز البند ويا البيع (شوف [orders.md](orders.md#البيع-الچيك-اوت)):

```json
{ "item_id": 3, "quantity": 24, "package": "dozen" }
```

- `quantity` **دايماً بالقطع**. السعر والمخزون ينحسبون منها بس.
- `package` **للمعلومة بس**. ينحفظ ويا البند ويطلع بالتفاصيل والفاتورة ("2 درزن")، بس ما يغيّر لا السعر ولا الكمية.
- المتوفر بالمخزون (`available_quantity` بـ [items.md](items.md)) بالقطع. لا تخلي البائع يختار أكثر منه.
