# API التطبيق — الأوردرات (v1)

عرض أوردرات المبيعات بالتطبيق: بحث، اختيار زبون، وترتيب.

> **المتبقي والمدفوع ما ينرسلون بالـ API أبداً** — ولا بأي endpoint. الذمم تنشاف بلوحة التحكم بس. الهيدرات والتوكن مشروحين بـ [login.md](login.md).

---

## عرض الأوردرات

```http
GET /api/v1/orders
Authorization: Bearer <التوكن>
```

يحتاج صلاحية `app.orders`، وبدونها يرجع `403`. الأوردرات المحذوفة ما تظهر أبداً.

### الباراميترات (كلها اختيارية)

| الباراميتر | القيم | الوصف |
|---|---|---|
| `search` | نص | يدوّر باسم الزبون، وإذا كانت القيمة أرقام يدوّر برقم الأوردر بعد |
| `customer_id` | رقم زبون | يعرض أوردرات هذا الزبون بس. زبون مو موجود يرجع `422` |
| `sort` | `date` أو `amount` | العمود. الافتراضي `date` |
| `direction` | `asc` أو `desc` | الاتجاه. الافتراضي `desc` |
| `per_page` | `1` – `100` | عدد الأوردرات بالصفحة. الافتراضي `25` |
| `page` | رقم | رقم الصفحة |

الباراميترات تتجمع سوا: `?search=علي&sort=amount&direction=desc` = أوردرات "علي" من الأغلى للأرخص.

### الترتيبات اللي تحتاجها بالشاشة

| المطلوب | الرابط |
|---|---|
| الأحدث أول (الافتراضي) | `/api/v1/orders` |
| الأقدم للأحدث | `/api/v1/orders?sort=date&direction=asc` |
| الأغلى للأرخص | `/api/v1/orders?sort=amount&direction=desc` |
| الأرخص للأغلى | `/api/v1/orders?sort=amount&direction=asc` |

### الجواب — `200`

```json
{
  "data": [
    {
      "id": 1,
      "date": "2026-08-26",
      "customer": { "id": 4, "name": "أحمد علي حسين" },
      "payment_type": { "value": "cash", "label": "كاش" },
      "amount": 140000,
      "total_amount": 140000,
      "items_count": 2,
      "notes": null
    }
  ],
  "links": { "first": "...", "last": "...", "prev": null, "next": "..." },
  "meta": { "current_page": 1, "last_page": 3, "per_page": 25, "total": 57 }
}
```

| الحقل | معناه |
|---|---|
| `payment_type.value` | `cash` أو `postpaid` — استعمله بالكود |
| `payment_type.label` | التسمية المترجمة حسب `Accept-Language` — اعرضها للمستخدم |
| `amount` | مجموع بنود الأوردر |
| `total_amount` | المبلغ النهائي المطلوب |
| `items_count` | عدد بنود الأوردر |

**الصفحات:** استعمل `meta.current_page` و `meta.last_page` للتمرير اللانهائي، أو `links.next` مباشرة — يرجع `null` بآخر صفحة.

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.orders` | `403` |
| باراميتر غلط (`sort` مو معروف، زبون مو موجود، `per_page` أكبر من 100) | `422` بنفس شكل الأخطاء بـ [login.md](login.md) |

### مثال

```bash
curl "http://localhost:8000/api/v1/orders?search=علي&sort=amount&direction=desc&per_page=10" \
  -H "Accept: application/json" \
  -H "Accept-Language: ar" \
  -H "Authorization: Bearer 12|kZ8mQ1w..."
```

## تفاصيل أوردر واحد

```http
GET /api/v1/orders/{id}
Authorization: Bearer <التوكن>
```

يحتاج صلاحية `app.orders`. هذا اللي تناديه لمن يضغط البائع على أوردر بالقائمة.

نفس حقول الأوردر بالقائمة، **وزيادة عليها `items`** — بنود البيع كاملة:

```json
{
  "data": {
    "id": 13,
    "date": "2026-09-16",
    "customer": { "id": 7, "name": "بصريات البصرة" },
    "payment_type": { "value": "postpaid", "label": "آجل" },
    "amount": 45000,
    "total_amount": 45000,
    "items_count": 1,
    "notes": null,
    "items": [
      {
        "id": 22,
        "item_id": 3,
        "name": "Aviator Sunglasses",
        "image": "http://localhost:8000/storage/items/aviator-sunglasses-iqB4F4.png",
        "quantity": 1,
        "package": { "value": "piece", "label": "قطعة" },
        "price": 45000,
        "total_price": 45000
      }
    ]
  }
}
```

| حقل البند | معناه |
|---|---|
| `item_id` | رقم المادة — ينفع تفتح بيه المادة |
| `name` | اسم المادة وقت ما تنقرا الحين |
| `image` | رابط صورة المادة الكامل، أو `null` |
| `quantity` | الكمية المبيعة **بالقطع** |
| `package.value` | التعبئة اللي انباع بيها البند: `piece` أو `dozen` أو `packet`. للمعلومة بس |
| `package.label` | اسم التعبئة المترجم. اعرضه مثلاً "2 درزن" = `quantity ÷ size` |
| `price` | سعر القطعة **وقت البيع** — مو سعر المادة الحالي |
| `total_price` | `quantity × price` |

> **مهم:** `price` محفوظ بالبند وقت البيع، فلو تغيّر سعر المادة بعدين، الأوردر القديم يضل يعرض سعره الأصلي. لا تحسب المجموع من سعر المادة الحالي.

**الفرق عن القائمة:** القائمة ترجّع `items_count` بس (رقم)، وما بيها `items` أبداً — حتى تضل خفيفة. البنود تجي من هذا الـ endpoint لحده.

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.orders` | `403` |
| أوردر مو موجود أو محذوف | `404` |

## فاتورة الأوردر — ملف PDF

```http
GET /api/v1/orders/{id}/invoice
Authorization: Bearer <التوكن>
Accept-Language: ar
```

يحتاج صلاحية `app.orders`. هذا اللي يستخدمه زر **"مشاركة الفاتورة"** بشاشة تفاصيل الأوردر.

> **الجواب مو JSON** — هو **ملف PDF** خام (بايتات). لا تحاول تفكّه كـ JSON.

| | |
|---|---|
| `Content-Type` | `application/pdf` |
| `Content-Disposition` | `attachment; filename="invoice-13.pdf"` |
| الحجم التقريبي | 100 – 150 كيلوبايت |
| اللغة | حسب `Accept-Language` — الفاتورة تطلع عربية كاملة بالاتجاه الصحيح، أو إنكليزية |

**شنو بالفاتورة:** رقم الأوردر وتاريخه ووقته، اسم البائع، طريقة الدفع، الزبون وهاتفه، البنود بكمياتها وأسعارها، المجموع والخصم والصافي، ومكان للتوقيع والملاحظات.
**وشنو ما بيها:** الكلفة والربح — أبداً، لأن هذا الملف ينعطى للزبون.

> **دليل تنفيذ كامل بالكود** لمشاركة الفاتورة على الواتساب: [share-invoice.md](share-invoice.md).

### شلون تستخدمه بالتطبيق

```
1. نزّل الملف من هذا الـ endpoint (مع هيدر التوكن).
2. خزّنه بملف مؤقت بالجهاز، مثلاً invoice-13.pdf
3. افتح شيت المشاركة مال النظام (share_plus بالفلاتر) وعطيه الملف
   → البائع يختار واتساب ويختار المحادثة
```

- **خزّن الملف بعد أول تنزيل** — مشاركته مرة ثانية تصير محلية بلا نت.
- الواتساب **ما يقبل مرفق من رابط مباشر** (`wa.me` يدزّ نص بس)، فالطريق الوحيد للملف هو شيت المشاركة.
- لمن يستلم الزبون الملف يكدر يفتحه ويطبعه من أي جهاز — ملف PDF عادي بحجم A4.

### الشكل يتغيّر من السيرفر

القالب موجود بالسيرفر ومشترك ويا طباعة لوحة التحكم. يعني أي تعديل على شكل الفاتورة (شعار، خط، ترتيب، جملة بالأسفل) يوصل التطبيق **فوراً وبلا إصدار جديد**. لا تبني الفاتورة بالتطبيق.

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.orders` | `403` |
| أوردر مو موجود أو محذوف | `404` |

الأخطاء ترجع **JSON** عادي، مو PDF — افحص `Content-Type` قبل ما تتعامل مع الجواب كملف.

## البيع (الچيك اوت)

```http
POST /api/v1/orders
Authorization: Bearer <التوكن>
```

يحتاج صلاحية `app.checkout`، وبدونها يرجع `403`.

### الطلب

```json
{
  "customer_id": 4,
  "payment_type": "postpaid",
  "notes": "يستلمها بكرة",
  "down_payment": 5000,
  "lines": [
    { "item_id": 3, "quantity": 24, "package": "dozen" },
    { "item_id": 7, "quantity": 1 }
  ]
}
```

| الحقل | إلزامي | الوصف |
|---|---|---|
| `customer_id` | ✅ | زبون موجود. ماكو بيعة بلا زبون |
| `payment_type` | ✅ | `cash` أو `postpaid` |
| `lines` | ✅ | بند واحد على الأقل |
| `lines[].item_id` | ✅ | مادة موجودة |
| `lines[].quantity` | ✅ | أكبر من صفر، و**بالقطع** دايماً |
| `lines[].package` | ❌ | `piece` أو `dozen` أو `packet` من [packages.md](packages.md). للمعلومة بس. إذا ما دزيته ينحسب `piece` |
| `notes` | ❌ | ملاحظة على الأوردر |
| `down_payment` | ❌ | الدفعة الأولية اللي دفعها الزبون ويا البيعة. **للآجل بس**. لا تدزها إذا ماكو دفعة |

**ملاحظتان مهمتان:**

1. **ما تدزّ سعر.** السعر ينأخذ من سعر بيع المادة بالداتابيس وقت البيع. أي `price` تدزّه ينتجاهل.
2. **ما تدزّ تاريخ.** تاريخ الأوردر هو تاريخ اليوم على السيرفر، مو ساعة الجهاز.

### الجواب الناجح — `201`

نفس شكل الأوردر بالقائمة، وبمبالغه محسوبة:

```json
{
  "data": {
    "id": 1,
    "date": "2026-09-16",
    "customer": { "id": 4, "name": "علي حسن" },
    "payment_type": { "value": "postpaid", "label": "آجل" },
    "amount": 4500,
    "total_amount": 4500,
    "items_count": 1,
    "notes": null
  }
}
```

> **المدفوع والمتبقي ما ينرسلون للتطبيق** — لا بهذا الجواب ولا بغيره. حسابات الذمم تنشاف بلوحة التحكم بس.

### الرفض — `422`

البيعة كلها ترفض ولا ينحفظ منها ولا بند. الأسباب:

| السبب | الرسالة (بالعربي) |
|---|---|
| مادة بلا سعر بيع | *المادة X ما إلها سعر بيع.* |
| سعر البيع أقل من الكلفة | *المادة X ما تنباع بأقل من سعر كلفتها.* |
| كمية صفر أو بالسالب | *الكمية لازم تكون أكبر من صفر.* |
| كمية ما تصير تعبئات كاملة (25 ويا `dozen`) — على `lines.N.quantity` | *الكمية لازم تكون تعبئات كاملة: كل درزن = 12 قطعة.* |
| تعبئة مو معروفة — على `lines.N.package` | رسالة التحقق العادية |
| زبون مو موجود | *الأوردر لازم يكون لزبون موجود.* |
| بلا طريقة دفع | *الأوردر لازم تكون بيه طريقة دفع.* |
| دفعة أولية ويا بيعة كاش | *الدفعة الأولية تنأخذ ويا البيع الآجل بس.* |
| دفعة أولية صفر أو سالبة | *الدفعة الأولية لازم تكون أكبر من صفر.* |
| دفعة أولية أكثر من مبلغ الأوردر | *الدفعة الأولية ما تكدر تكون أكثر من مبلغ الأوردر.* |
| كمية أكثر من المتوفر بالمخزون | *ماكو كفاية من المادة X: باقي بس Y.* |

```json
{
  "message": "المادة كرسي ما تنباع بأقل من سعر كلفتها.",
  "errors": { "items": ["المادة كرسي ما تنباع بأقل من سعر كلفتها."] }
}
```

> اعرض `message` للمستخدم مباشرة، وخلّي السلة مفتوحة حتى يصلّح البند.

### مثال

```bash
curl -X POST http://localhost:8000/api/v1/orders \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -H "Accept-Language: ar" \
  -H "Authorization: Bearer 12|kZ8mQ1w..." \
  -d '{"customer_id":4,"payment_type":"cash","lines":[{"item_id":3,"quantity":3}]}'
```
