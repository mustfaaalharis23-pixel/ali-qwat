# API التطبيق — استلام البضاعة (v1)

صفحة الاستلام بالتطبيق: قائمة فواتير الشراء بمراحلها، وقراءة باركود ملصق الكارتونة حتى تصير الفاتورة "تم الاستلام".

> كل الروابط هنا تحتاج صلاحية `app.receiving`، وبدونها يرجعون `403`. الهيدرات والتوكن مشروحين بـ [login.md](login.md).

---

## قائمة فواتير الشراء

```http
GET /api/v1/purchase-invoices
Authorization: Bearer <التوكن>
```

فواتير الشراء بس. الفواتير العامة والفواتير المحذوفة ما تظهر أبداً.

### الباراميترات (كلها اختيارية)

| الباراميتر | القيم | الوصف |
|---|---|---|
| `stage` | `in_production` · `manufactured` · `received_at_warehouse` · `on_the_way` · `received` | يعرض الفواتير اللي بهاي المرحلة بس. مرحلة مو معروفة ترجع `422` |
| `direction` | `asc` أو `desc` | الترتيب حسب تاريخ الفاتورة. الافتراضي `desc` (الأحدث أول) |
| `per_page` | `1` – `100` | عدد الفواتير بالصفحة. الافتراضي `25` |
| `page` | رقم | رقم الصفحة |

الباراميترات تتجمع سوا: `?stage=on_the_way&direction=asc` = الفواتير اللي بالطريق من الأقدم للأحدث.

### المراحل بترتيبها

| `stage.value` | بالعربي |
|---|---|
| `in_production` | قيد التصنيع |
| `manufactured` | تم التصنيع |
| `received_at_warehouse` | تم الاستلام في المخزن |
| `on_the_way` | في الطريق |
| `received` | تم الاستلام في العراق |

### الجواب — `200`

```json
{
  "data": [
    {
      "id": 12,
      "number": "PI-12",
      "name": "علي 3",
      "supplier": "علي",
      "date": "2026-09-20",
      "stage": { "value": "on_the_way", "label": "في الطريق" }
    }
  ],
  "links": { "first": "...", "last": "...", "prev": null, "next": "..." },
  "meta": { "current_page": 1, "last_page": 2, "per_page": 25, "total": 31 }
}
```

| الحقل | معناه |
|---|---|
| `number` | رقم ملصق الكارتونة، نفس اللي بالباركود |
| `name` | اسم الفاتورة: اسم المورد ورقمها عنده |
| `supplier` | اسم المورد |
| `date` | تاريخ الفاتورة |
| `stage.value` | المرحلة. استعمله بالكود |
| `stage.label` | المرحلة مترجمة حسب `Accept-Language`. اعرضها مثل ما هي |

> **مرحلة جديدة ممكن تنضاف.** إذا جات `stage.value` ما تعرفها، لا يطيح التطبيق: اعرض `label`.

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.receiving` | `403` |
| باراميتر غلط (`stage` مو معروفة، `direction` غلط، `per_page` أكبر من 100) | `422` |

## فاتورة شراء وحدة ويا سطورها

```http
GET /api/v1/purchase-invoices/{id}
Authorization: Bearer <التوكن>
```

نفس حقول القائمة، وفوكها مجاميع الفاتورة وسطورها بترتيبها، حتى موظف الاستلام يحسب شنو وصل. **ما بيها أي فلوس**: لا مبلغ ولا سعر ولا كلفة.

### الجواب — `200`

```json
{
  "data": {
    "id": 12,
    "number": "PI-12",
    "name": "علي 3",
    "supplier": "علي",
    "date": "2026-09-20",
    "stage": { "value": "on_the_way", "label": "في الطريق" },
    "cartons_count": 6,
    "quantity": 150,
    "cbm": 2.25,
    "items": [
      {
        "id": 40,
        "item_id": 5,
        "name": "Classic Round Glasses",
        "image": "http://host/storage/items/frames.jpg",
        "boxes_count": 10,
        "pieces_per_packet": 12,
        "quantity": 120,
        "boxes_per_carton": 4,
        "cartons_count": 3,
        "cbm": 0.75
      }
    ]
  }
}
```

| الحقل | معناه |
|---|---|
| `cartons_count` | مجموع كراتين الفاتورة |
| `quantity` | مجموع القطع بالفاتورة |
| `cbm` | الحجم الكلي للفاتورة |
| `items[].name` · `image` | اسم المادة ورابط صورتها (`null` إذا ما عدها صورة) |
| `items[].boxes_count` | عدد الباكيتات |
| `items[].pieces_per_packet` | القطع بالباكيت الواحد |
| `items[].quantity` | القطع = الباكيتات × القطع بالباكيت |
| `items[].boxes_per_carton` | الباكيتات بالكارتونة الوحدة |
| `items[].cartons_count` | الكراتين = الباكيتات ÷ الباكيتات بالكارتونة، والكارتونة الناقصة تنحسب وحدة |
| `items[].cbm` | حجم السطر = الكراتين × حجم الكارتونة |

> القائمة وجواب قراءة الباركود ما يجيبون هالمجاميع ولا `items`، بس هذا الرابط.

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.receiving` | `403` |
| الفاتورة مو موجودة، أو محذوفة، أو فاتورة عامة مو شراء | `404` |

## قراءة باركود الكارتونة — الاستلام

```http
POST /api/v1/purchase-invoices/receive
Authorization: Bearer <التوكن>
```

```json
{ "barcode": "PI-12" }
```

دز النص **مثل ما قراه الماسح** من ملصق الكارتونة. الفاتورة تصير "تم الاستلام" فوراً، من أي مرحلة جانت.

### الجواب — `200`

نفس شكل الفاتورة بالقائمة، وزيادة `already_received`:

```json
{
  "data": {
    "id": 12,
    "number": "PI-12",
    "name": "علي 3",
    "supplier": "علي",
    "date": "2026-09-20",
    "stage": { "value": "received", "label": "تم الاستلام" }
  },
  "already_received": false
}
```

- كل كراتين الفاتورة عليها نفس الملصق، فقراءة كارتونة ثانية **مو خطأ**: يرجع `200` و `already_received: true`.
- باركود مو ملصق فاتورة شراء يرجع `422` على `barcode` برسالة جاهزة: *هذا الباركود مو ملصق فاتورة شراء.*

### الأخطاء

| الحالة | الكود |
|---|---|
| بلا توكن أو توكن باطل | `401` |
| بلا صلاحية `app.receiving` | `403` |
| باركود فارغ أو مو ملصق فاتورة شراء | `422` |
