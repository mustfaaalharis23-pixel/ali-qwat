# API التطبيق — الدخول (v1)

هذا الملف لمطوّر تطبيق المبيعات. يشرح شلون التطبيق يسجّل دخول البائع، ويخزّن التوكن، ويستخدمه بكل طلب بعدها.

---

## 1. الأساسيات

| | |
|---|---|
| **العنوان** | `http://localhost:8000/api/v1` (بالتطوير) — يتبدّل بعنوان السيرفر بالنشر |
| **الصيغة** | JSON بالطلب والجواب |
| **النسخة** | `v1` بالمسار. أي تغيير كاسر راح يجي بـ `v2`، و `v1` تضل تشتغل |

### الهيدرات بكل طلب

```http
Accept: application/json
Content-Type: application/json
Accept-Language: ar
```

- `Accept: application/json` **إلزامي** — بدونه الأخطاء ترجع HTML مو JSON.
- `Accept-Language` ياخذ `ar` أو `en`. كل الرسائل ترجع بهاي اللغة. إذا ما تندز، اللغة الافتراضية `en`.
- بالطلبات المحمية يزيد عليهن:

```http
Authorization: Bearer <التوكن>
```

## 2. تسجيل الدخول

```http
POST /api/v1/login
```

### الطلب

```json
{
  "user_id": 7,
  "password": "secret",
  "device_name": "iPhone 15 — Ali"
}
```

| الحقل | إلزامي | الوصف |
|---|---|---|
| `user_id` | ✅ | **معرّف الموظف** (رقم). يشوفه المسؤول بعمود المعرّف بصفحة المستخدمين بلوحة التحكم وينطيه للموظف |
| `password` | ✅ | الباسورد |
| `device_name` | ✅ | اسم الجهاز، يظهر بلوحة التحكم حتى المسؤول يعرف منو داخل ومنين، ويكدر يسحب التوكن لجهاز معيّن. خلّيه ثابت لنفس الجهاز (مثلاً موديل الجهاز + اسم الموظف) |

### الجواب الناجح — `200`

```json
{
  "token": "12|kZ8mQ1w...",
  "user": {
    "id": 7,
    "name": "علي حسن",
    "email": "seller@example.com",
    "is_cashier": true,
    "permissions": ["app.orders", "app.checkout"]
  }
}
```

- **`token` يرجع مرة وحدة بس** — السيرفر يحفظ بصمته مو نصّه، فما ينقدر يرجّعه مرة ثانية. إذا انضاع، الحل الوحيد تسجيل دخول جديد.
- خزّنه بمخزن آمن: **Keychain** بالـ iOS، **EncryptedSharedPreferences / Keystore** بالأندرويد. لا تخزّنه بملف عادي ولا بـ SharedPreferences مكشوف.
- **التوكن ما ينتهي** بمدة. يبطل بس لمن يسوي البائع تسجيل خروج، أو لمن يسحبه المسؤول.
- `permissions` هي **شاشات التطبيق** المسموحة لهذا الموظف — اخفِ أي شاشة مو موجودة بالقائمة:

| القيمة | الشاشة |
|---|---|
| `app.orders` | شاشة الطلبات |
| `app.checkout` | البيع (الچيك اوت) |

  القائمة تكبر بالمستقبل، فاقرأها كنص ولا تفترض إنها محصورة بهاتين القيمتين.

### الأخطاء

| الحالة | الكود | شنو صار |
|---|---|---|
| معرّف أو باسورد غلط | `422` | الرسالة: *هذي البيانات ما تطابق سجلاتنا.* |
| الحساب معطّل أو محذوف | `422` | الرسالة: *هذا الحساب معطّل. راجع المسؤول.* |
| حقل ناقص أو معرّف مو رقم | `422` | رسالة الحقل الناقص |

شكل أي خطأ `422` واحد دائماً:

```json
{
  "message": "هذي البيانات ما تطابق سجلاتنا.",
  "errors": {
    "user_id": ["هذي البيانات ما تطابق سجلاتنا."]
  }
}
```

> اعرض `message` للمستخدم مباشرة — هي جاهزة وبلغة الطلب.

## 3. بيانات المستخدم الحالي

```http
GET /api/v1/me
Authorization: Bearer <التوكن>
```

يفيد لمن يفتح البائع التطبيق ويريد يتأكد إن توكنه بعده شغّال.

### الجواب — `200`

```json
{
  "data": {
    "id": 7,
    "name": "علي حسن",
    "email": "seller@example.com",
    "is_cashier": true,
    "permissions": ["app.orders", "app.checkout"]
  }
}
```

> لاحظ: هنا البيانات داخل `data`، بينما بجواب الدخول تجي تحت `user` مباشرة.

---

## 4. تسجيل الخروج

```http
POST /api/v1/logout
Authorization: Bearer <التوكن>
```

### الجواب — `204` (بلا محتوى)

يحذف توكن **هذا الجهاز بس**. أجهزة البائع الثانية تضل داخلة. بعدها امسح التوكن من الجهاز ورجّع المستخدم لشاشة الدخول.

---

## 5. التوكن المرفوض — `401`

أي طلب محمي بلا توكن، أو بتوكن محذوف أو غلط:

```json
{
  "message": "Unauthenticated."
}
```

**شلون يتعامل التطبيق:** أي `401` من أي endpoint = التوكن مات (سحبه المسؤول أو انسوى خروج). امسح التوكن المخزون وودّي المستخدم لشاشة الدخول فوراً. لا تحاول تجدّده — ماكو تجديد تلقائي بهذا النظام.

---

## 6. مثال كامل (cURL)

```bash
# دخول
curl -X POST http://localhost:8000/api/v1/login \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -H "Accept-Language: ar" \
  -d '{"user_id":7,"password":"secret","device_name":"iPhone 15 — Ali"}'

# طلب محمي
curl http://localhost:8000/api/v1/me \
  -H "Accept: application/json" \
  -H "Authorization: Bearer 12|kZ8mQ1w..."

# خروج
curl -X POST http://localhost:8000/api/v1/logout \
  -H "Accept: application/json" \
  -H "Authorization: Bearer 12|kZ8mQ1w..."
```

### الصلاحيات — مهمة

`permissions` تكَلّك أي شاشة تعرضها للموظف، **والسيرفر يفحصها بعد**: أي طلب لشاشة مو مسموحة يرجع `403` بهذا الشكل:

```json
{ "message": "ما عندك صلاحية لهذي الشاشة." }
```

| الـ endpoint | يحتاج |
|---|---|
| `GET /api/v1/orders` · `GET /api/v1/orders/{id}` · `GET /api/v1/orders/{id}/invoice` | `app.orders` |
| `POST /api/v1/orders` | `app.checkout` |
| `GET /api/v1/items` | `app.checkout` |
| `GET /api/v1/customers` | `app.orders` **أو** `app.checkout` |
| `GET /api/v1/me` · `POST /logout` | ولا شي — أي توكن صالح |

يعني إخفاء الشاشة بالتطبيق مو حماية لحاله؛ هو بس حتى ما يشوف الموظف شاشة ترجعله خطأ.
